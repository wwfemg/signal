# 怎么加一条记录

这个项目只做一件事：**把每只票的时间节点记清楚**——什么时候进入视野、触发它的事实是什么、在等哪个公告、什么条件算看错、后来发生了什么。
买还是卖，每个人自己判断。我们不替任何人做决定。

## 四条红线（违反的直接关闭，不讨论）

1. **不写买卖建议、不写目标价、不写"会涨到多少"。** 只写事实、日期、节点。
2. **不收费、不拉付费群、不带单、不留联系方式。**
3. **每条记录必须有公告出处**：公告标题＋披露日期。写"听说""内部消息""某群里说"的一律不收。
4. **记录只增不删。** 看错了就把状态改成"作废"，写清依据，原文保留。成绩单的价值就在于把错的也留着。

## 证据分级（写进记录里）

| 标记 | 含义 |
|---|---|
| ✅ | 公告原文证实 |
| 🟡 | 间接迹象（如股东名册变化、工商信息） |
| ❓ | 猜测 |

猜测可以大胆提，但**下结论前必须回到公告原文**。巨潮全文检索是模糊匹配（会拆词命中），命中数不可直接引用；罕见人名较可靠，机构名和常见姓名必须抽查原文。

## 一条记录的五栏

```json
{
  "code": "600520",
  "name": "三佳科技",
  "found": "2026-05",
  "line": "国资入主线",
  "trigger": "触发它的事实。必须写公告标题和日期，别人能查到。",
  "waiting": "在等哪个具体公告（受理／过会／注册／批复／摘帽／解禁…）",
  "falsify": "什么情况算看错。提前写死，事后不许改。",
  "status": "等",
  "review": "后来发生了什么。定期回来补。"
}
```

`status` 只能填：`等`（等公告）、`观察`、`超时`（该来的公告迟迟不来）、`应验`、`作废`、`否决`。

**`falsify` 是这个项目最重要的一栏。**事先写不出"什么算看错"的，说明这条记录还不成立，先别提交。

## 工具也欢迎改

`tools/` 下面的脚本谁都可以改进或者新加。新工具的要求：只用 Python 标准库，
一条命令能跑，输出是人能直接看懂的文字，抓取间隔不少于 2.5 秒。

## 两种参与方式

**A. 提名一只票（不用会编程）**
开一个 Issue，选"提名一只票"，按表单填。我们核实公告后录入台账。

**B. 直接改台账（会用 Git）**
改 `ledger.json`，提交 PR。合并前会逐条核对公告原文。

## 我们会回什么

- 核实通过：录入台账，公开可见。
- 核实不通过：说明卡在哪一条（通常是没有公告出处，或者写不出"什么算看错"）。
